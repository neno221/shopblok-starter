# Next session: run T12 (Medusa DAL skeleton and wiring page), in the cloud

The M0 plan runs in a Claude Code cloud environment (decision D16 in [plans/M0.md](plans/M0.md)). T11, the proxy and the `[market]` root, is done: `apps/storefront/src/proxy.ts` serves clean public URLs from the internal `/{key}/…` routes (`/` is `<html lang="el-CY">`, `/us` `en-US`, `/ch/fr` `fr-CH`, and so on), redirects `/cy` to `/` with a 301, answers 404 (from `global-not-found`, in English) for an internal key such as `/el-cy`, and leaves `/admin`, `/api`, `/next`, `/_next` and files alone ([SETUP.md](SETUP.md#proxy-and-the-market-root-t11)). Every check in T11's Verify list passed: 27 Playwright tests against `next start`, a warm cache adds **0.0088 ms** at p95 (limit 5 ms), `/admin` still logs in and out, 82 new unit tests (288 in the storefront), 20 mutations each caught, and the root `typecheck`, `lint`, `test` and `build` pass with no `.env` and no database (the second `pnpm build` is a turbo hit). It was also run live on a Brazil-only and a Mongolia-only map, saved while the server ran (30 s and 54 s to reach the pages). The plan changed in four ways, all written into it (SETUP.md "Proxy and the `[market]` root (T11)", "What should change in the plan"):
1. **The proxy reads the map from `/next/markets`, not from Payload.** The plan's cold-miss limit was 150 ms; importing Payload into the proxy cost **549.6 ms**, so T11 used the plan's own fallback: a prerendered route returns the `use cache` copy of the map, and the proxy keeps it 30 s. The proxy bundle has no Payload now. The cost: in a self-hosted process Payload still starts once, inside the route, and that landed on a request (320 to 370 ms) in two of my runs and not in a third (57 ms); I did not isolate why. D10 says so now.
2. **A not found is a rewrite to `/`**, the one path no route can match (a rewrite to `/_not-found` is taken as a market key and shows Next's default page).
3. **`/cy/` is two hops** (Next's 308 for the slash, then the proxy's 301). I left `skipTrailingSlashRedirect` off (decision below).
4. **The rewrite keeps the query string**, which the plan's `new URL('/' + key + path, req.url)` does not.
