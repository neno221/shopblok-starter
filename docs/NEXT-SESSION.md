# Next session: run T11 (`proxy.ts` and the `[market]` root), in the cloud

The M0 plan runs in a Claude Code cloud environment (decision D16 in [plans/M0.md](plans/M0.md)). T10, the markets library, is done: `apps/storefront/src/lib/markets/` turns a public URL into a market and back (SPEC §8.5), lists the hreflang alternates (SPEC §12), and reads Payload's `markets` global with a 30 s cache, and the `markets` global now checks each language's Medusa locale against Medusa's 51 ([SETUP.md](SETUP.md#markets-library-t10)). Every check in T10's Verify list passed: 145 new table tests cover the seeded map, a per-country domain, and D17's Brazilian, Mongolian, US-only and Greek-only shops with no code change; 24 mutations were each caught; and the library was also run against the real `payload` database in `next dev` and `next start` (a map saved through the admin shows up in about a minute, an empty global keeps the last good map, and a fresh production process over an empty global answers 500 with a message that says what to do). `lib/shell-markets.ts` and its 6 tests are gone, the root layout reads the map, and `pnpm build` still works with no `.env` and no database. The plan changed in five ways, all written into it (SETUP.md "Markets library (T10)", "What should change in the plan"):
1. **The layout reads the map through `'use cache'`** (`getRenderMarketMap()`, tag `global:markets`); the proxy calls `getMarketMap()` directly. A prerendered root layout can't call the in-process cache (`Date.now()`): the build failed until it was cached.
2. **The fixtures stand in for the global in development and while `next build` runs, never in production.** The plan said "development only"; CI builds with no database. Production answers 500 with `MarketMapError` when the global is empty, so `next start` needs the global filled (a curl recipe is in SETUP.md until T13's bootstrap does it).
3. **Public URLs have no trailing slash** (`/us`, not `/us/`); SPEC's slash is notation.
4. **A market on its own domain is an absolute URL, and the main host still serves every market** (a decision of mine, below).
5. **`medusaLocale` is checked against the 51 codes, not against the row's language**, and no migration was needed.

All the owner's open questions are decided now (plan D18 to D23: every default stays, and `apps/storefront/AGENTS.md` stays), so nothing in the environment, the config or the repo changed for them.
