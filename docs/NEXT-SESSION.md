## What S2 found, and what is yours to decide

**Verdict: PASS**, the plan's rule applied as written. One app ran five index definitions over the same data: candidate A (per-locale fields), A' (one multilingual field) and B (one index per locale) on a prototype Meilisearch provider, and A and A' on `search-postgres`. T1, T2, T6 pass on all five; a changed translation is searchable in 0.4 to 1.7 s through the `translation.*` events; a language added in the store is searchable with no restart for B and A', and A needs `db:migrate` plus a restart (12 s and 9 s); the reindex of 1,002 products takes 15 to 17 s on every candidate, and B is 22 MB against 6 to 9 MB for the others; Mongolian is found by its own words on both engines. **ADR 0002 proposes: Meilisearch (M6) keeps one index per locale (B); the keyless Postgres default (M3) uses A' (one multilingual index); one transform serves both; a small `/store/search` middleware turns the request's locale into the options of the active provider, so the storefront stays provider-agnostic; a bulk translation import ends with `reindex`.**

**Five readings of the plan's rules are yours to confirm** (I changed no rule; ADR 0002, "Decision", has the evidence). Each has a default that stays unless you say:

- **R1. B or A on Meilisearch?** The PASS rule requires B there, and it passed; A passed every test on Meilisearch too (it fails only T7's "no restart") and is 2.3 times smaller, with no fan-out code in the provider. **Default: B, as the rule says.** If you would rather have one definition for both providers (A on both), the evidence supports it, at the price of a restart for a new language.
- **R2. T7's "no code change" for A:** an edit of `SUPPORTED_LOCALES` in `src/config/markets.ts`, `db:migrate`, a restart. **Default: A' on Postgres, which needs none of it.**
- **R3. T4's "worker mode":** measured in one process that is both server and worker, over the in-memory bus and over Redis; a separate worker process was not run. **Default: accepted as measured.**
- **R4. T8 has no threshold** ("recorded"); the plan said four locales and the index had six. **Default: as recorded.**
- **R5. T9 expected Mongolian "found by trigram only":** it is found by its exact words with the provider's default configuration. **Default: as recorded.**

**Worth a look:** the S2 session found four Medusa 2.21.2 behaviours that the design depends on, and the merged assumptions spec guards them: `updateTranslationsWorkflow` with the `selector` form its own docs show first throws and emits no event; `query.graph(…, { locale })` leaves nested objects in English unless their `id` is selected; there is one `translation.created` event per row (a bulk import is a backlog); and `search-postgres` rejects `search_options.locales`. My first Meilisearch fan-out also wrote a reindex's documents to the wrong indexes, and every test still passed until T8 counted them: the tests now search each candidate right after its reindex.

The prototype is one commit, `ca361b2`, on `claude/amazing-volta-3sn94u`; the next commit removes it from the tree (D13). It stays in `main`'s history because PRs merge with a merge commit (G2).
