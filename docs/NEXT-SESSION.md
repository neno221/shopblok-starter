The M0 plan runs in a Claude Code cloud environment (decision D16 in [plans/M0.md](plans/M0.md)). T13, `pnpm bootstrap`, is done: `scripts/bootstrap.ts` with `scripts/lib/{env-file, exec, checks, output}.ts` and, for the Payload half, `apps/storefront/src/scripts/bootstrap-payload.ts` ([SETUP.md](SETUP.md#pnpm-bootstrap-t13)). With the compose stack up it takes a clone to a working setup in 41 s (both `.env` files with generated secrets, both databases migrated, the seeds, the Medusa admin, the publishable key, the Payload admin and `integrations` user, the `markets` global), and a second run changes nothing: 0 done, both `.env` files and the rows of all 170 tables the same. What it built was checked end to end: `next build` and `next start` from the written `.env` serve `/` in Greek with `49,00 €`, `/us` with `$54.00` and `/ch/fr` with `48.00 CHF`, the Playwright `markets` suite passes (28), the Payload login with the dev credentials and `GET /api/integrations/me` with the written API key both work. D17 was run both ways (Brazil added to `config/markets.ts` on fresh volumes gives `/store/regions` Brazil, `/store/locales` `pt-BR` and two `min_price_brl <= 100` hits; on an existing database the index gets a new version, and undoing the edit plans another). `pnpm typecheck`, `lint`, `test` (18 + **78** + 375 + 85) and `build` pass in CI's state (no `.env`, no database; the second `pnpm build` is a turbo hit, `55ms >>> FULL TURBO`), and 35 mutations were each caught. The plan changed in seven ways, all written into it ([SETUP.md](SETUP.md#pnpm-bootstrap-t13), "What should change in the plan"):
1. **A command that asks a question is stopped, not answered.** `payload migrate` after Payload's dev push asks `(y/N)`, and with stdin closed it waited for ever; the first version of bootstrap hung there. `run()` ends a command whose output asks, and step 7 prints the remedy.
2. **"Every step `= unchanged`" means no `✓ done`.** Steps 10 and 11 stay `↷ skipped`; the preflight and (from T14) the doctor write nothing, so they report `= unchanged`.
3. **The publishable key is the one value bootstrap replaces.** It belongs to the database; `docker compose down -v` makes a new one, so the run ends `✓ done (replaced the key of an earlier database)` and says that the storefront has to be built again. The admin password and the Payload API key are reused from `.env`.
4. **The Payload API key lives only in the backend `.env`.** Payload keeps a hash and never returns the key; the script checks it by authenticating with it, and creates or re-keys the "Medusa sync" user.
5. **The two admins share `DEV_ADMIN_EMAIL` (`admin@example.com`) and `DEV_ADMIN_PASSWORD`**, with one gap handled and not exercised live (Medusa admin exists, no stored password, empty Payload `users`).
6. **`extractPublishableKey` is not imported from the backend** (its package is CommonJS to TypeScript, `TS1287`); `extractMarker` in `scripts/lib/output.ts` reads the same line.
7. **`--no-demo` runs the demo seed with `skip`, and the seed decides**, so a production bootstrap must pass `--no-demo` (D7).
