# Next session: run T15 (root scripts and dev loop), in the cloud

The M0 plan runs in a Claude Code cloud environment (decision D16 in [plans/M0.md](plans/M0.md)). T14, `pnpm run doctor`, is done: `scripts/doctor.ts` with `scripts/lib/{integrations, report, doctor-checks, markets-check, http, load-exports}.ts` and, for the Payload half, `apps/storefront/src/scripts/doctor-payload.ts` ([SETUP.md](SETUP.md#pnpm-run-doctor-t14)). It reports which of SPEC §10's seven integrations are live (and names each fallback), probes Postgres, Redis, Meilisearch, Mailpit, Medusa `/health` and the storefront, checks the env (secrets, publishable key, Payload key, email verification, Vercel without `S3_*`, production without `REDIS_URL`), and compares `apps/backend/src/config/markets.ts` with the storefront's map (D17, D19); with `--online` it also calls the running servers with the keys. It writes nothing, takes 3.1 to 3.5 s, and is `bootstrap`'s step 11. The D17 scenario was run live with Brazil in four states (edited; region seeded without `db:migrate`; migrated, restarted and on both sides; map without config), and each state gave the doctor line it should. `pnpm typecheck`, `lint`, `test` (18 + **187** + 375 + 85) and `build` pass in CI's state (no `.env`, no database; the second `pnpm build` is a turbo hit, `56ms >>> FULL TURBO`), and 46 mutations were each caught. The plan changed in seven ways, all written into it ([SETUP.md](SETUP.md#pnpm-run-doctor-t14), "What should change in the plan"):
1. **Redis is live after bootstrap, so "every integration on fallback" is true of the five third-party ones, not of all seven.** With `REDIS_URL` blank all seven are `fallback`. T16's assertion and §7 item 5 now say "every third-party integration".
2. **Keys for a provider that doesn't exist yet change nothing.** Each integration has a `wired` flag; only Redis is wired in M0, so Meilisearch (whose keys `.env.example` sets) is `fallback` until M6. M6 flips the flags.
3. **A server that isn't running here is a warning**, because bootstrap runs doctor before anything is started. Postgres and Redis down are errors; `--strict` makes every warning fail (the go-live check).
4. **Payload's CLI exits 0 without running anything in about 1 run in 20** (`payload run` and `payload migrate`, found by doctor's tests; cause not found). T13's step 7 could have read that as "nothing to migrate". `retryWhileSilent` (`scripts/lib/exec.ts`) now repeats such a run in doctor and in bootstrap. T16's `e2e-smoke` would have met it once in 20 runs.
5. **The search index has two answers for a missing currency** (`Unknown field` and `not facetable`); both are "missing". Found only by running the scenario, as the plan's recipe says.
6. **A market taken out of `config/markets.ts` leaves its region in Medusa** (the seed never removes one); doctor reports it (`medusa-orphans`), and deleting it in the admin works.
7. **The `markets` global is read with `payload run`, as a production process**, so Payload cannot create a missing database (D18); and not at all when the Postgres check failed (a foreign server). Both were run live.
