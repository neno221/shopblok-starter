The plan changed in six ways, all written into it (SETUP.md, "What should change in the plan"):

2. **`turbo.json`: `MEDUSA_DISABLE_TELEMETRY` is in the `dev` task's `passThroughEnv`.** Strict environment mode dropped it, so `pnpm dev` queued Medusa telemetry events even with the opt-out set in the shell. Three runs: old file with the variable set queued `CLI_START` and `CLI_START_COMPLETED`, the new file queued none, and with the variable unset it queued them as before.

Left as built (decision below).

The storefront and Payload's `/admin` come up without Medusa; the catalog part of `/` shows its error state with a log line that names the cause.
5. **Stopping `pnpm dev`:** `^C` in a terminal ends all 12 processes in 1 s. A session has no terminal: `kill -INT` of the turbo process does the same (a signal to `pnpm dev` alone does nothing, because pnpm ignores SIGINT). CLOUD.md says so now.

Things for you to decide; none blocks T16 and each has a default that stays unless you say:
- **`--env-mode=loose` for `dev` only (T15 item 3 above).** `turbo run dev --env-mode=loose` in the root script would let the shell win over `.env` under `pnpm dev`, as it does in `bootstrap` and `doctor`. Strict mode's cache-safety reason does not apply to an uncached task, but loose mode also stops telling you which variables a task needs, and no real use needs it today. **Default: as built** (strict, three variables passed through).
- **Proxy variables under `pnpm dev`.** `HTTPS_PROXY`, `NO_PROXY` and `NODE_EXTRA_CA_CERTS` are dropped. Nothing the dev servers do in M0 goes to the internet except telemetry, so no use exists yet; M6 (Stripe, Resend, R2) will have one behind a proxy. **Default: add them then.**
- **"Every integration on fallback" (T14 item 1).** The plan's wording can't hold, because Redis is a real, wired part of the local stack. The default is the third-party reading: `integrations.filter(i => i.kind === "third-party")` all `fallback`. If you would rather have `doctor --json` say `fallback` for Redis too in a bootstrapped setup, one way is to stop writing `REDIS_URL` into `.env.example`, which would send everyone to the in-memory modules in development. **Default: as built.**
- **Payload's silent exit (T14 item 4).** The retry hides it; it doesn't explain it. If it matters to you, the fix is upstream (Payload's `bin.js` loads the script through `tsx`'s `module.register` hooks) and needs an issue on `payloadcms/payload`, which a cloud session can't open. **Default: leave the retry.**
- **Orphan regions (T14 item 6).** Doctor reports a region that `config/markets.ts` no longer lists; nothing removes it, because deleting a region that has orders or carts is not something a seed should do. **Default: report only.**
- **Catalog data in the shell or in streamed parts (SETUP.md T12 item 2).** With Cache Components a failure in a streamed part cannot change the HTTP status, so "backend down gives 5xx" cannot hold for a `◐` page that streams its data (T15 saw it again: `/` answers 200 with the backend down). The choice matters for M1, when the first real catalog page arrives: (a) keep catalog data in `Suspense` parts, as the wiring page does; (b) put it in the static shell with `use cache` (SPEC §8.1 says "cached shell + tags" for the home, PDP and PLP), which keeps the shop up through a backend outage (the shell is served stale) but needs a build-time stand-in for CI builds that have no backend, like D10's fallback for the `markets` global; (c) add a status route for monitors (for example `/next/status`, 503 when Medusa or Payload does not answer). **Default: leave the wiring page as it is and decide at M1.**
- **S1 has still not run.** T12 added evidence, none of it a verdict: the SDK and the Local API work inside `use cache` (through `lib/cache.ts`) in `next dev` and `next start`, `revalidateTag(tag, { expire: 0 })` gave fresh content on the next request and `'max'` within the first, a failed call caches nothing, `/[market]` is `◐` with `cacheComponents` and `partialPrefetching` on. Not run: the draft-isolation load test, the admin suite, the matrix. **Default: T16 next, then S1 on a `spike/*` branch.** Say if you want S1 first.
- **Bootstrap replaces a stale publishable key and keeps a plain-text dev password** (T13 items 3 and 5). The key is replaced because a wiped database makes the old one fail every request (T15's `infra:reset` run did exactly that: `✓ done (replaced the key of an earlier database)`); the admin's `DEV_ADMIN_PASSWORD` sits in the git-ignored backend `.env` (mode 600) and `medusa user -p` takes it as an argument, so it is visible in `ps` for 4 seconds. It is a throwaway account on a local stack. **Default: as built.**
- **Carried over, unchanged:** the first request after a start can wait 320 to 370 ms on a self-hosted server (Payload starts inside the map route; fix idea: `instrumentation.ts`, decided at M7), `/cy/` is two hops (308 then 301; `skipTrailingSlashRedirect` stays off), and a saved map reaches the proxy in 30 to about 65 s (M4's hook can shorten it). **Default: leave all three.**
